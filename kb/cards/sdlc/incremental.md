The Incremental model splits the product into parts and delivers them in successive increments, each built through a mini cycle of design, implementation, and test. The first increment carries core functions; later ones add features. Early increments reach users sooner and reveal problems while change is still cheap. It fits products where the full requirement set is understood but can be released in stages, such as an infotainment system shipped with basic media first and navigation later. It fails when the architecture is not settled up front, because late increments then force rework of early ones. Typical roles: project manager, architect, developers, testers. Deliverables: a working release per increment, an integration plan, and updated test evidence. Safety evidence must still be produced for every increment that touches safety functions.
