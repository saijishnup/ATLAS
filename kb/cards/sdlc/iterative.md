The Iterative model starts with a rough version of the whole system and improves it over repeated cycles, refining requirements, design, and code each time. Unlike incremental delivery, each cycle revisits the entire product rather than adding a new slice. It fits projects where requirements are only partly known at the start and improve as users react to early versions, for example a driver-assistance HMI whose layout needs several review rounds. It fails when the budget or deadline is fixed without room for extra cycles, and when no clear stopping rule exists, because refinement can continue without end. Typical roles: product owner, developers, testers, user representatives. Deliverables: a working version per cycle, a review record, and an updated requirement list. Traceability needs discipline as requirements move between cycles.
