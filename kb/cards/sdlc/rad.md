Rapid Application Development builds working software fast through prototyping, reusable components, and tight user involvement, using short fixed time-boxes instead of long upfront planning. Users review working versions early and often, and the design evolves from that feedback. It fits small to medium products with clear business scope, modular structure, and users available to review daily, for example an internal diagnostics dashboard. It fails on large or tightly coupled systems, hardware-heavy work, and safety-critical functions, because speed and light specification leave little room for formal verification or evidence. Typical roles: small cross-functional team, user representatives, tester. Deliverables: working prototypes, refined increments, minimal design notes. In automotive, use for tools and non-safety front ends only.
