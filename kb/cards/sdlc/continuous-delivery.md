Continuous Delivery keeps software always in a releasable state through an automated pipeline: build, test, package, and deploy to staging, with release by a business decision. Small changes and automated checks reduce risk per release. It fits products with frequent updates and strong automated test coverage, such as an infotainment app store or a telematics client. It fails when verification needs slow hardware-in-the-loop runs, manual approvals, or regulator sign-off per release, unless those are fitted into the pipeline as gates. Typical roles: developers, test automation engineers, release manager. Deliverables: automated pipeline and release candidates. In automotive each release may also need update-management evidence.
